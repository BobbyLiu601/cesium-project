## 实现边界

- 物理计算使用动态加载的 `ammojs-typed`，场景在项目自己的 Cesium `Viewer` 中渲染，不引入 Three.js 或参考站的 `CesiumMeshVisualizer`。
- 场景按参考项保留车辆、软旗面、软绳刚体球、软体受击和可断裂结构五类核心行为，并以功能等价而非逐像素一致验收。
- 车辆支持 `W/S/A/D`，旗子和球支持 `Q/A`；所有场景同时提供屏幕按钮、暂停/继续和重置。软体与断裂体场景支持画布单击或屏幕按钮发射小球。
- 参考页硬编码的天地图 Token、脚本和页面外壳均未复制。项目只读取自己的可选 `VITE_TIANDITU_TOKEN`；无 Token 或影像服务失败时，物理场景仍保持可用。
- `ammojs-typed` 生成的 `CreateFromTriMesh` 绑定会调用该 wasm 构建未导出的 `_free`。软体场景在对应运行时补一个受控的临时缓冲兼容函数，不影响刚体/软体的正常销毁。

## 验证

单元测试通过物理场景工厂覆盖五个场景的创建、控制、暂停、重置、状态和销毁清理；组件测试覆盖 `3.4` 的顺序、深链和菜单；Playwright 在真实浏览器中验证五条路由、可见动画、键盘/按钮操作、发射、暂停/重置以及关闭后的卡片焦点恢复。
